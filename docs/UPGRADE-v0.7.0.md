# NAS 成就服务升级

v0.7.0 成就的历史记录和月底清理由 NAS 执行，需升级 NAS 服务；仅更新手机或 Windows 程序不会启用自动清理。旧服务仍可正常同步，成就页面会提示升级。

## 使用者现有 DX4600 项目

先在两端同步未上传修改，并备份原 data 目录。当前对话提供的私有更新 compose.yaml 沿用原密钥、端口、运行用户以及 `./data:/data`，只更新嵌入的服务器程序。在 NAS 原项目目录中替换 compose.yaml，然后重新部署原项目；保留原项目位置和 data，勿新建到其他目录。私有配置含密钥，不要上传 GitHub。

todo-sync 持续运行、/health 返回正常后，两端点击同步。“成就”页升级提示消失即表示已收到 NAS 成就数据。

## 自行构建的服务

将源码包的新 server/app.py、server/Dockerfile 更新到原源码目录，保留原 .env 和数据目录。在原 Compose 项目重新构建并启动 todo-sync。不要使用清除数据卷的命令。数据库新增成就与归档表，原任务格式和数据库身份保持兼容。

## 自动清理的具体范围

- 按北京时间（UTC+8），服务器每分钟检查一次；服务停机时，下次启动或同步补做遗漏月份。
- 首次启用从当前月开始；以前的月份不自动清理。
- 周按本月内周一至周日分段，月初月末可为短周。按安排日期计算，完成率 ≥80% 得星；有任务的所有周段达标则绿，否则红，没有任务则灰。
- 月内星星是实时预览，月底按 NAS 已收到的数据定格历史。结算和清理在同一个 SQLite 事务中完成；失败则回滚并重试。
- 清理已结束月份中有日期且有分类的全部任务，包括未完成任务。无日期、收件箱、未分类保留。有日期的未分类任务仍参与完成率统计。
- 清理前保存完整任务归档到同一 NAS 数据库；普通在线 SQLite 备份也包含成就与归档。清理通过删除记录同步到两端。
- 月末及时同步。未同步离线修改与清理冲突时保留冲突供选择；结算后才新到达的过期待办保留，历史结果不回改，可改期或手动处理。
- 跨年自动显示新的十二个月，旧年成就继续保留。
