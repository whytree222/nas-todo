# NAS 习惯成就服务升级

1. 两端先同步。停止原Docker项目，备份整份原data目录；可能存在的SQLite WAL/SHM文件一并保留。
2. 使用本聊天提供的私有v0.11.0配置，在**原项目、原目录**替换compose.yaml，保留原data、端口、用户和访问令牌，重新部署。不要新建空数据目录，无需todo-init。
3. 确认todo-sync持续运行，原ZeroTier地址的/health返回正常。两端安装新版并同步，成就页不再显示习惯成就升级提示即可验证。

私有配置包含同步密钥，仅用于自己的NAS，不上传或转发。使用源码构建者，从Release的nas-todo-server-v0.11.0.zip更新原server/app.py和Dockerfile，并在原项目重建服务；保留.env及挂载。

## 新结算规则

- 待办完成率与习惯达标率**分别≥80%**，才获得该周段星星。一类无计划时忽略该类；两类均无计划不评分。月份仍按所有有计划周段是否达标确定绿/红，无计划月份为灰。
- 每个习惯的每个计划日计1天，次数达到当天目标算1个达标日；同日重复点击不增加权重。休息日不参与，实时统计只计算截至今天的习惯日，月底按整月结算。
- NAS保存按日期生效的目标和执行日历史。修改或删除从修改当天生效，过去日期仍使用原目标、原计划；新客户端断网时保存计划历史，联网后同步。
- 新规则从升级当天启用，已有习惯从当天开始计计划日，避免凭空增加升级前的义务。新建习惯按本地创建日期记录，最早不早于NAS新规则启用日。日期以NAS北京时间为准，明显超前的设备日期会限制到NAS当天。
- 旧的已结算月份保持原记录，不追溯重算。月底先归档再清理本月有日期、有分类的全部待办（含未完成），保留无日期、收件箱、未分类；习惯、打卡历史和计划历史不清理。
- 同一个SQLite数据库增加习惯计划历史表，数据库身份、原待办、成就和同步密钥保留。在线备份包含新表。

旧客户端仍可同步基础任务和个人记录，看到原待办口径的兼容成就视图；请两端都升级到v0.11.0，以查看相同的新成就规则。不要降级或清除尚有未上传内容的新版应用。
